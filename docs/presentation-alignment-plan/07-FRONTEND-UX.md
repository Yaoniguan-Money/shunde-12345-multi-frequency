# 07｜前端页面最终规格

## 1. 导入与研判页

页面只围绕三个真实动作：上传文件、选择模型、研判整个批次。

必须：

- 删除“研判数量”输入和 1—300 提示；
- 导入完成显示“成功导入 N 张，本次将研判全部 N 张”；
- 展示本地、云端两张 Provider Profile 卡；
- 云端卡文案由后端返回“千问，已适配”；
- 每张卡显示已验证、未验证、不可用或验证失败；
- “验证链路”调用真实 validate 接口；
- 用户在点击“开始研判”前可自由切换；
- 任务创建后显示已锁定的 profile，当前任务不允许中途切换；
- 下一任务可重新选择；
- 进度显示目标工单、已处理、失败、已生成事项；
- 后端失败原因可见，并允许按同一 scope 恢复。

建议文案：

```text
成功导入 100 张工单
本次将研判全部 100 张
模型路径：云端模型（千问，已适配）
已处理 68 / 100 张，已识别 71 个 AI 研判事项
```

## 2. 工单列表页

### 2.1 顶部全量概览

同一筛选范围内展示：

- 工单总数；
- 已分析；
- 未处理；
- 已分析无事项；
- 失败；
- AI 研判事项总数；
- 进入多频组的工单数。

全部来自 `/work-orders/overview`。当前页 20 条只显示在分页区域。

### 2.2 固定解释 100/103

“AI 研判事项总数”旁长期显示 Info/Tooltip：

> 一张工单可能同时包含多个独立诉求，系统会拆成多个 AI 研判事项，因此事项数可能大于工单数。当前为 100 张工单、103 个事项。

数字使用接口动态值，说明中的当前数字也随 scope 更新。不能只弹一次 Toast。

### 2.3 筛选区

- 全文/工单号搜索；
- 分析状态；
- 诉求事项分类三级级联；
- 来源标记，可选；
- 紧急状态；
- 高频状态。

诉求事项分类从完整附录 A tree/facets 获取，显示代码、名称、路径和计数。分析状态不再与分类混在同一个下拉框。

### 2.4 表格列

| 列 | 数据来源 |
|---|---|
| 工单号 | 原始工单 |
| 工单标题 | 原始标题 |
| 诉求事项分类 | 当前 active Event Instance 的 DB44 节点 |
| 来源标记 | 原 title tags，可弱化 |
| 分析状态 | AnalysisOutcome |
| AI 事项数 | 当前工单 Event Instance 数 |
| 多频状态 | 所属聚类及 FrequencyStatus |
| 受理时间 | reported_at |
| 导入时间 | imported_at，可选次级列 |
| 操作 | 详情 |

没有合法 `reported_at` 时显示“未知”，不得把导入时间换个标题冒充受理时间。

## 3. Dashboard

### 3.1 必须整块删除

删除：

- “质量指标”标题；
- 准确率/Gold Set 卡；
- 质量状态灯；
- “暂无 Gold Set”说明；
- 对应占位空格和布局容器。

删除后重新排版，不保留隐藏节点或空卡。

### 3.2 保留的真实指标

- 工单总数；
- AI 研判事项总数；
- 关联事件组数；
- 高频事件数；
- 分析状态；
- 附录 A 一级分类分布，可下钻二级、三级。

所有卡片使用后端全量投影。没有真实受理时间聚合前，不展示模拟趋势。

## 4. 工单详情

展示：

- 不可变原始标题和正文；
- 当前投诉、历史背景、部门回复、当前诉求分段；
- 每个 AI 事项；
- 每个事项的 DB44 完整分类路径；
- 焦点项目/对象、地点、责任单位；
- evidence span；
- reported_at 和来源；
- Provider、模型、pipeline、taxonomy 版本；
- 人工纠正入口及审计历史。

一张工单有多个事项时逐项展示，不把 2—3 个事项揉回一个摘要。

## 5. 多频事件列表

默认优先展示达到门槛、频次高、时间新的组。卡片明确区分：

```text
5 张不同工单 / 5 个 AI 研判事项
高频：3 个自然日内达到 3 张及以上工单
受理窗口：2025-03-31 至 2025-03-31
```

状态只显示：高频、未达到高频门槛、时间证据不足。不得出现“低频”。

搜索“美的”可以返回相关工单/事项，但不能因为搜索命中而暗示它们属于同一聚类。

## 6. 多频事件详情

必须展示：

- canonical 项目/对象；
- DB44 分类路径；
- 不同项目叫法的别名映射；
- 成员工单号、标题、受理时间；
- 为什么关联的对象、分类、地点、时间和处理链证据；
- 冲突和未知；
- 高频 winning window 和不同工单计数；
- AI 判断版本；
- 工作人员确认、拆分、合并和纠正。

美涂士组满足门槛时必须显示“高频”，不能显示低频或普通事件。

## 7. 处置表单

新增处置记录表单：

- 删除“附件编号”输入；
- 删除对应 React state、校验和请求字段；
- 不使用 CSS 隐藏；
- 历史记录已有附件引用时允许只读查看；
- AI 判断状态和业务处置状态保持两条独立状态线。

## 8. 最终现场 Demo 流程

1. 上传政府提供的 100 条真实脱敏工单；
2. 页面显示成功导入 100 张、将研判全部 100 张；
3. 选择“云端模型（千问，已适配）”并开始；
4. 完成后显示 100 张工单、103 个 AI 事项及固定解释；
5. 进入多频事件，打开系统自然生成的美涂士欠薪组；
6. 展示五张工单、3 月 31 日、项目别名、`080508` 和高频状态；
7. 搜索“美的”，展示冰箱、工业区、道路项目属于不同对象和分类；
8. 展示工作人员可确认或纠正。

标准产品流程即 Demo 流程，不建设案例专用页面、预制按钮或演示数据分支。

## 9. 前端验收要点

- 页面无研判条数输入；
- 本地/云端选择真实影响任务请求；
- 附录 A 完整分类可筛选；
- 100、103、20 三种数字不混淆；
- 类型、分析状态、来源标记完全分离；
- 无质量指标板块；
- 无附件编号输入；
- 无低频标签；
- 错误不被轮询吞掉；
- 美涂士证据和高频结果可见。
