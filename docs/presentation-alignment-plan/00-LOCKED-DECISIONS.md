# 00｜锁定产品决策

本文件是所有专项计划的共同上游。若后续实现与本文件冲突，以本文件为准，并先更新 ADR，不得由某个 Agent 私自改变产品定义。

## 1. 研判范围

1. 一个导入批次成功导入 `N` 张工单，默认目标范围就是这 `N` 张。
2. 前端删除“研判数量”输入；API 删除 `max_work_orders` 和 `selection_mode`。
3. 内部可以分块、排队、限并发、断点续跑，但不能减少业务目标范围。
4. 资源不足时任务明确排队或失败，不得截断后返回“完成”。

## 2. 模型选择和真实链路

1. 用户在每次任务开始前选择“本地模型”或“云端模型”。
2. 任务创建时持久化 Provider Profile 快照；任务运行中不可切换。
3. 下一次任务可重新选择，不能依赖修改全局环境变量。
4. 本地路径必须真实执行 LLM、Embedding、结构化输出和最小端到端研判。
5. 云端当前适配千问，但领域层、任务处理器和数据模型不出现厂商分支。
6. 任一模型失败都不得静默切到另一模型，也不得返回规则伪造结果。

## 3. 标准分类

1. 类型体系完整对齐 DB44/T 2479—2024 附录 A，而不是截图中的 14 个一级名称就算完成。
2. 14 个一级、99 个二级、515 条三级记录都进入版本化目录。
3. 来源数据已提供有效标准代码时，代码到目录节点的映射必须是确定性的，不调用 AI 猜名称。
4. 来源没有标准代码时，分类器只能选择标准目录中的 `classification_node_id`，不得生成自由文本类型充当标准分类。
5. `title_tags` 只能叫“来源标记”，不能再显示为“类型标签”。
6. 分析状态、标准分类、来源标记是三个独立维度。

## 4. 工单、事项和页面数字

1. Work Order 是一张原始群众工单。
2. AI 研判事项是从工单中拆出的独立问题；一张工单可以有多个事项。
3. 100 张工单产生 103 个事项是合法的一对多关系，不能强压成 100。
4. 多频频次按不同 `work_order_id` 计数，不能按事项数计数。
5. 全量统计由后端按同一筛选范围聚合；当前页 20 条只属于分页信息。
6. 前端长期显示说明：“一张工单可能包含多个独立诉求，因此 AI 研判事项数可能大于工单数。”

## 5. 高频规则

1. 高频事件定义为：同一事件在任意连续 3 个自然日内达到 3 张及以上不同工单。
2. 窗口使用来源系统的 `reported_at`；历史回复日期、事发日期和导入时间不能替代。
3. 满足门槛必须标记 `high_frequency`，不得显示成“低频”或“未达到”。
4. 未达到门槛使用 `not_reached`；日期证据不足使用 `insufficient_date_evidence`。
5. 产品中不建立 `low_frequency` 状态或标签。

## 6. 同事件业务语义

“同一事件”指同一现实焦点对象上的同类集中问题或兼容处理链，不等于文本相似，也不要求是同一投诉人。

正向判断至少需要：

- 焦点项目/场所/企业等现实对象相同；
- 问题类型相同或明确兼容；
- 受理时间窗口兼容；
- 不存在地点、对象、问题或处理链硬冲突。

只有“欠薪”“美的”等通用词相同不能建立同事件边。

## 7. 演讲稿验收主线

1. 美涂士五张工单必须通过通用链路自然归为一个欠薪集中事件。
2. 四种项目叫法必须归一为同一现实项目，且依据可见。
3. 世贸国风滨江欠薪不能因为同为欠薪混入。
4. 美的冰箱、美的第五工业区、美的大道项目必须保持分离，并给出对象和问题类型差异。
5. 上述案例只允许出现在 Gold Set、测试名和评测报告中，生产算法不得特判。

## 8. 前端明确删除项

1. Dashboard 的“质量指标 / 质量状态灯 / 暂无 Gold Set”整个板块删除并重新排版，不留空位。
2. 新增处置记录中的“附件编号”输入、状态、校验和请求字段删除。
3. 历史附件引用可以只读保留，避免破坏既有审计。
4. 删除未接真实接口、只显示“功能开发中”的假入口。

## 9. 性能目标

1. 云端 100 条干净数据不能继续以十几分钟作为可接受基线。
2. 优化顺序为：减少无价值模型调用、连接复用、批量数据访问和持久化、阶段流水化、最后才是云端有界并发。
3. 云端和本地使用不同 Execution Policy，不能共享一个全局并发参数。
4. 本地模型不得通过显著增加并发 KV Cache、显存或 RAM 换速度。
5. 性能优化不能牺牲全批次范围、分类目录、同事件证据或 Gold Set 质量。

## 10. 不降级原则

- 不使用 TODO、stub、静态 JSON、演示分支、预制聚类或测试 Provider 进入生产路径。
- 不吞异常、不假成功、不静默 fallback。
- 不把未知实体、地点或时间猜成确定事实。
- 不把案例写进 prompt、SQL、前端或规则分支。
- 不删除失败测试换取绿灯。
